# Развёртывание на Windows 10

Эта инструкция для сервера под Windows 10 без Docker. Всё работает службами Windows и поднимается само после перезагрузки, без входа пользователя в систему:

```
телефоны и ноутбуки
   │  интернет, порты 80 и 443
   ▼
Caddy (служба KassaProxy): HTTPS, сертификат выпускается сам
   │  127.0.0.1:3000, только внутри этой машины
   ▼
Kassa (служба KassaApp): сервер на Node.js, отдаёт API и сайт
   │  127.0.0.1:5432, только внутри этой машины
   ▼
PostgreSQL 16 (служба postgresql-x64-16)
```

Наружу открыты только порты 80 и 443. Приложение и база слушают только саму машину.

> **Что здесь не проверено.** Скрипты прогнаны на Linux: сборка с нуля, миграции, обновление, подготовка базы, проверка через настоящий Caddy с HTTPS и с `TRUST_PROXY`, синтаксис и совместимость с Windows PowerShell 5.1 (статически). Ни разу не выполнялось на самой Windows то, что есть только в ней: установка служб (WinSW), права (`icacls`, `sc.exe`), правила брандмауэра, `powercfg`. Если на каком-то шаге что-то идёт не так, пришлите текст ошибки: исправим скрипт. Раздел «Если что-то не работает» внизу.

## Что нужно заранее

- Windows 10 (64 бита), учётная запись с правами администратора.
- Постоянный (статический) IP-адрес сервера.
- Порты 80 и 443 доступны из интернета: открыты у провайдера или хостера и в роутере, если он есть. Порт 80 нужен не только для первого сертификата, но и для продления (раз в два месяца).
- Верные дата и время (Параметры, Время и язык, «Синхронизировать»). При неверных часах не выпускается сертификат и ломаются сессии.
- Интернет на сервере (установка, GitHub, выпуск сертификата).

## 1. Подготовка, один раз

### 1.1 Установить программы

| Что | Откуда | Заметки |
|---|---|---|
| Node.js 22 (LTS) | https://nodejs.org | MSI, всё по умолчанию. После установки откройте новое окно PowerShell. |
| Git for Windows | https://git-scm.com | Всё по умолчанию. |
| PostgreSQL 16 | https://www.postgresql.org/download/windows/ | Установщик EDB. **Запомните пароль пользователя `postgres`**, порт оставьте 5432. Stack Builder не нужен. |

### 1.2 Скачать два файла

- **Caddy**: https://caddyserver.com/download, платформа Windows amd64. Скачается файл вроде `caddy_windows_amd64.exe`: сохраните его как `C:\kassa\tools\caddy.exe` (папку создайте).
- **WinSW** (оболочка, которая делает из программы службу Windows): https://github.com/winsw/winsw/releases, последняя версия 2.x, файл для .NET Framework (в названии `WinSW`, например `WinSW-x64.exe` или `WinSW-net461.exe`). Положите куда угодно, скрипт скопирует его сам. Запомните путь.

### 1.3 Получить код

Откройте **PowerShell от имени администратора** (правый щелчок по «Пуск», «Windows PowerShell (администратор)»). Не ISE: он принимает любое сообщение программ за ошибку.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass   # разрешает запуск скриптов, только в этом окне
git clone https://github.com/SalikhovIbrohim/kassa.git C:\kassa\app
cd C:\kassa\app
git checkout claude/pensive-edison-be5dwy                    # ветка, в которой сейчас код; позже будет main
```

Если репозиторий закрытый, Git сам откроет окно входа в GitHub.

Эту строку с `Set-ExecutionPolicy` нужно повторять в каждом новом окне PowerShell, прежде чем запускать скрипты.

### 1.4 База, настройки, первая сборка

```powershell
.\deploy\windows\setup.ps1
```

Скрипт спросит пароль `postgres`, создаст в PostgreSQL роль и базу `kassa` (роль без лишних прав), запишет файл настроек `C:\kassa\config\kassa.env` со случайным паролем базы (только администраторам и системе) и соберёт приложение. Повторный запуск безопасен: что есть, остаётся.

В файле настроек уже стоят `NODE_ENV=production` (cookie сессии получают флаг `Secure`) и **`TRUST_PROXY=127.0.0.1`**: Caddy стоит на этой же машине и сообщает серверу настоящий адрес клиента. Без этой строки защита входа от перебора пароля видит всех как один адрес, и один посторонний может заблокировать вход всем, включая владельца.

### 1.5 Не давать серверу уснуть

```powershell
.\deploy\windows\power.ps1
```

Выключает сон и гибернацию при питании от сети. Если после отключения электричества машина сама не включается, найдите в BIOS пункт «Restore on AC Power Loss» (или «After power failure») и поставьте «Power On».

## 2. Пользователи и начальные остатки

Пользователей и начальные остатки заводит разработчик, интерфейса для этого нет. Скрипт `kassa.ps1` запускает те же команды с настройками этой машины:

```powershell
.\deploy\windows\kassa.ps1 create-user --login ivan --role cashier --name "Иван Петров"    # спросит пароль
.\deploy\windows\kassa.ps1 create-user --login owner --role viewer --name "Владелец"
.\deploy\windows\kassa.ps1 set-opening-balance --currency RUB --amount 45000
.\deploy\windows\kassa.ps1 set-opening-balance --currency USD --amount 300
.\deploy\windows\kassa.ps1 list-users
.\deploy\windows\kassa.ps1 help                                                          # все команды
```

## 3. Службы и HTTPS

Адрес. Пока нет своего домена, берём бесплатный адрес на вашем IP: к IP-адресу через дефисы добавьте `.sslip.io`. Для `203.0.113.5` это `203-0-113-5.sslip.io`. Он сам указывает на этот IP, сертификат для него выпускается бесплатно (Let's Encrypt). Когда будет домен (#10), поменяется одна команда, см. ниже.

```powershell
.\deploy\windows\install-services.ps1 -Site 203-0-113-5.sslip.io -WinSW C:\путь\к\WinSW-x64.exe
```

Скрипт: пишет Caddyfile, ставит службы `KassaApp` и `KassaProxy` (запуск автоматический, через пару минут после старта Windows, перезапуск при сбое через 10, 30, 60 секунд), делает их работающими от `NT AUTHORITY\LocalService` (а не от всемогущего SYSTEM), открывает порты 80 и 443 в брандмауэре Windows, запускает и проверяет, что приложение отвечает. PostgreSQL уже работает своей службой. Повторный запуск заменяет службы.

Первый запуск Caddy просит у Let's Encrypt сертификат: это до минуты.

**Смена адреса позже** (купили домен): `.\deploy\windows\install-services.ps1 -Site kassa.example.ru` и поправьте у домена A-запись на IP сервера.

## 4. Проверка после установки: с телефона, не с сервера

С самого сервера всё всегда выглядит хорошо. Проверять нужно снаружи.

1. На телефоне **в мобильной сети** (не в Wi-Fi сервера) откройте `https://203-0-113-5.sslip.io`. Должна открыться страница входа, без предупреждения о сертификате. Если адрес не открывается, а по IP сервер виден, возможно, сеть в России не разрешает имя `sslip.io`: тогда нужен свой домен (#10).
2. Войдите, внесите пробный приход и расход, посмотрите журнал.
3. Если под рукой есть ноутбук с Node.js и копией репозитория, проверка одной командой (на самом сервере она тоже запускается, но из-за NAT публичный адрес может не открываться изнутри):

   ```powershell
   $env:KASSA_CHECK_PASSWORD = "пароль кассира"
   node deploy\check.mjs https://203-0-113-5.sslip.io --login ivan
   ```

   Проверка смотрит: сервер и база отвечают, сайт отдаётся, манифест на месте (без него приложение не поставить на экран «Домой»), API просит вход, порт 80 перенаправляет на https (через него продлевается сертификат), вход работает и cookie с флагами `Secure` и `HttpOnly`. Выходит с кодом 1, если что-то не так.
4. **`TRUST_PROXY`**: в журнале приложения `C:\kassa\logs\KassaApp.out.log` не должно быть строки «TRUST_PROXY is not set». Для проверки руками: с одного телефона введите 21 неверный пароль (под разными логинами). Этому телефону ответят «подождите», а с устройства в другой сети (мобильный интернет вместо Wi-Fi) другой логин по-прежнему входит.
5. Установка на экран «Домой» (iPhone): Safari, «Поделиться», «На экран Домой».

## 5. Обновление и откат

Перед обновлением сделайте копию базы (до готовых скриптов резервного копирования, #7, это одна команда):

```powershell
$env:PGPASSWORD = "пароль postgres"
New-Item -ItemType Directory -Force C:\kassa\backups | Out-Null
& "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U postgres -Fc -f "C:\kassa\backups\before-update.dump" kassa
```

Обновление одной командой:

```powershell
cd C:\kassa\app
.\deploy\windows\update.ps1
```

Скрипт останавливает приложение (Caddy продолжает работать, посетитель увидит страницу с ошибкой, а не мёртвый адрес), забирает код (`git pull`), ставит пакеты, собирает, применяет миграции базы, запускает приложение и проверяет, что оно отвечает. Если проверка не проходит, он говорит об этом и печатает команду отката.

**Откат** на прежнюю версию: та же команда с номером версии (коммитом или тегом), который печатает скрипт при ошибке или показывает `git log`:

```powershell
.\deploy\windows\update.ps1 -Ref 1a2b3c4
```

Миграции базы идут только вперёд. Если новая версия меняла базу, откат кода может не подойти к ней, и тогда нужна копия, сделанная до обновления:

```powershell
# остановить приложение, затем:
& "C:\Program Files\PostgreSQL\16\bin\pg_restore.exe" -U postgres --clean --if-exists -d kassa "C:\kassa\backups\before-update.dump"
```

Чтобы собрать и применить миграции без остановки служб (например, первый раз), есть `.\deploy\windows\build.ps1`.

## 6. Перезагрузка сервера и питание

- Служба `KassaApp` ждёт PostgreSQL (зависимость) и запускается автоматически, `KassaProxy` тоже. После перезагрузки ничего делать не нужно, входить в Windows не нужно. Через пару минут проверьте: `node deploy\check.mjs http://127.0.0.1:3000`, и откройте сайт с телефона.
- Windows может сама перезагрузиться после обновлений. Чтобы это не пришлось на рабочее время, задайте «Период активности» (Параметры, Обновление и безопасность, Центр обновления Windows). В Windows 10 Pro можно точнее: `gpedit.msc`, Конфигурация компьютера, Административные шаблоны, Компоненты Windows, Центр обновления Windows, «Настройка автоматического обновления» (4: загрузка и установка по расписанию, например в 03:00). Названия пунктов зависят от сборки Windows.
- Не запускайте обновления Windows в рабочее время: перезагрузка обрывает работу кассиров на несколько минут (работа без связи появится в тикете #13).
- Если выключается свет, смотрите пункт про BIOS в 1.5.

## 7. Где что лежит

| Что | Где |
|---|---|
| Код | `C:\kassa\app` (клон репозитория) |
| Настройки и пароль базы | `C:\kassa\config\kassa.env` (не в репозитории) |
| Caddyfile | `C:\kassa\config\Caddyfile` |
| Журналы служб | `C:\kassa\logs\KassaApp.out.log`, `KassaApp.err.log`, `KassaProxy.err.log`, `caddy-access.log` (сами ротируются) |
| Службы | `C:\kassa\services\KassaApp\`, `KassaProxy\` (WinSW и его XML) |
| Сертификаты Caddy | `C:\kassa\caddy\data` (стоит включить в резервную копию) |
| База | в данных PostgreSQL (`C:\Program Files\PostgreSQL\16\data`) |

Управление службами: `Get-Service KassaApp, KassaProxy`, `Restart-Service KassaApp` (в PowerShell администратора) или `services.msc`. Удалить службы (данные остаются): `.\deploy\windows\uninstall-services.ps1`.

## 8. Если что-то не работает

- **Скрипт останавливается с красной строкой.** Прочитайте её: сообщения написаны так, чтобы сказать, что делать (например, чего не хватает).
- **Служба не запускается.** Смотрите `C:\kassa\logs\KassaApp.err.log` и `KassaApp.wrapper.log`. Запустите приложение вручную, чтобы увидеть ошибку: `node --env-file=C:\kassa\config\kassa.env server\dist\main.js` (в `C:\kassa\app`, после остановки службы). Если ручной запуск работает, а служба нет, возможно, мешают права: переустановите службы с `-ServiceAccount LocalSystem` и сообщите, что это помогло.
- **502 Bad Gateway на сайте.** Приложение не запущено или упало: `Get-Service KassaApp`, журнал выше.
- **Сертификат не выпускается.** Порт 80 или 443 закрыт у провайдера, в роутере или занят другой программой (`netstat -ano | findstr ":80 "`; частые виновники: IIS и другие веб-серверы). Смотрите `C:\kassa\logs\KassaProxy.err.log`. У Let's Encrypt есть лимиты на частые выпуски: подождите час или возьмите свой домен.
- **PostgreSQL виден снаружи.** Не должен. Проверка с другого компьютера: `Test-NetConnection <IP сервера> -Port 5432` должна сообщить, что порт закрыт. Если открыт, найдите правило брандмауэра PostgreSQL (`Get-NetFirewallRule -DisplayName "*postgres*"`) и отключите его: приложению внешний доступ не нужен.
- **Неверное время.** `w32tm /resync` в PowerShell администратора.
- **Две копии службы после переустановки.** `.\deploy\windows\uninstall-services.ps1`, затем снова `install-services.ps1`.

## 9. Безопасность в двух словах

- База и приложение доступны только с этой машины, наружу 80 и 443.
- Службы работают без прав администратора (`LocalService`), роль базы не может ничего, кроме своей базы.
- Пароль базы лежит только в `C:\kassa\config\kassa.env`, прочитать его могут администраторы, система и служба. В репозитории секретов нет.
- Пароль `postgres` в скрипты не записывается: его спрашивают один раз при подготовке.
- Копии базы (#7, #9) нужно хранить на другом носителе: потеря диска иначе означает потерю денег.
